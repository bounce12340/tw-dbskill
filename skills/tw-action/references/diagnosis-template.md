# 完整診斷：欄位要求與示例

使用者要求完整診斷，或材料豐富、命中多個訊號時使用。沒有內容的小節省略，不寫空標題。

---

## 模板

```markdown
# 執行力診斷

## 你卡在哪
{該做卻沒做的事；卡了多久；開始過幾次、在哪一步中斷}

## 先排除的情況
{僅在涉及資金、健康、照護等限制時寫}
- 真實約束：{哪些限制可以用事實描述}
- 它排除了：{哪種做法在當前條件下不可行}
- 約束內還能做：{更小、更低風險的版本}

## 我看到的訊號
- 主訊號：{A–F 之一}：依據：「{使用者原話}」或 {使用者的具體行為}
- 次訊號：{如有}：依據：{同上}

## 不做給你帶來了什麼
{目的論判斷：不做保住了什麼，做了要承擔什麼}
{標註：判斷 / 待驗證假設；假設要寫出能驗證它的事實}

## 解法
1. {針對主訊號的具體動作}
2. {……}
3. {……}

## 今天就做的一步
- 動作：{具體做什麼}
- 完成標準：{做到什麼程度算完成}

## 一句話
{一句直指核心的話，有依據；使用「你不是在 X，你是在 Y」時，X 必須是使用者說過的話}

> 這是基於 dontbesilent 方法的執行力診斷，不替代心理諮詢。如果你有持續的情緒困擾，請尋求專業心理諮詢師或醫生的幫助。
```

---

## 欄位要求

| 欄位 | 要求 |
| --- | --- |
| 你卡在哪 | 用使用者的事實描述，不加評價 |
| 先排除的情況 | 只在真實困難判斷有結果時出現；先承認，再分析 |
| 我看到的訊號 | 每個訊號必須附依據；沒有依據的訊號不列 |
| 不做給你帶來了什麼 | 區分判斷和假設；不替使用者編造動機 |
| 解法 | 跟主訊號對應，從 `signals.md` 的解法中選取並結合使用者情況具體化 |
| 今天就做的一步 | 一個動作，有完成標準，今天能完成 |
| 一句話 | 可省略；寫的話必須能從前面的依據推出 |

---

## 示例

> 使用者：我早就想好了要做個人 IP，選題也列了 50 個，但三個月了一條影片都沒發。每次開啟剪映就覺得還沒準備好，想先把燈光和話筒買好再說。

```markdown
## 你卡在哪
做個人 IP 的想法定了三個月，選題列了 50 個，影片一條沒發。每次卡在開啟剪映之後，結論都是「還沒準備好」。

## 我看到的訊號
- 主訊號：E 完美主義：依據：「每次開啟剪映就覺得還沒準備好」，三個月沒有一次發布。
- 次訊號：B 用思考替代行動：依據：選題列到 50 個，規劃持續增加，發布始終為零。

## 不做給你帶來了什麼
判斷：不發，就不會有人看到你的第一條影片，也就不會出現「播放很低」這個結果。你可以一直保留「等裝置齊了我能做得很好」的想象。買燈光和話筒，是把被評價的時刻再往後推一次。

## 解法
1. 裝置凍結：手頭的手機和自然光就是這一階段的全部裝置；
2. 從 50 個選題裡隨便挑一個，不挑最好的；
3. 發布標準降到「說完一個完整觀點、畫面能看清」；
4. 發出後只記錄兩項資料：播放和評論裡提到的具體問題。

## 今天就做的一步
- 動作：用手機拍一條一分鐘以內的影片併發布；
- 完成標準：影片已經在平台上公開可見。

## 一句話
你說「還沒準備好」，可你缺的是一次發布；燈光和話筒只會把被評價的時刻再往後推。

> 這是基於 dontbesilent 方法的執行力診斷，不替代心理諮詢。
```
