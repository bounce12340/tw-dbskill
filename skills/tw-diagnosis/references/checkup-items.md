# 體檢：七項檢查清單

七項檢查一次跑完。每項給出結論（透過 / 不透過 / 部分透過 / 依據不足）和一兩句依據；依據來自使用者材料時直接引用，來自推斷時標「假設」。

## 1．印鈔機檢查

商業模式是一臺對 input 有固定要求的機器。

- Input：要求投入什麼？時間、技能、資金、流量、人脈。
- Output：input 滿足時，能穩定產出什麼？
- 可替代性：換一個人喂同樣的 input，能不能產出同樣的 output？
  - 能：機器本身成立。
  - 不能：生意依賴特定的人，這臺機器還沒有獨立存在。

## 2．道德檢查

這個模式逼經營者做好人還是做惡人？

- 免費分享會讓收入增加：好模式。
- 必須誇大、製造焦慮或隱瞞資訊才能成交：壞模式。在壞模式裡努力做好人，代價會一直由經營者承擔；更現實的做法是換模式。
- 每多賺一筆錢都在透支口碑或信任：看起來是個人品牌生意，實際在按流量生意的邏輯消耗自己。

## 3．定價檢查

- 有幾個價格帶？彼此差多少？
- 引流款和利潤款的價差太小時，買家會把它們當成同一個產品，利潤款賣不動。dontbesilent 的經驗口徑：價差在 5～15 倍之間，差不到 5 倍就有問題。
- 引流款在指望自身賺錢：通常賺不到。引流款的任務是把人帶到利潤款面前。
- 收入規模還小的知識付費，最常見的問題出在定價。
- 價格由供需決定，和成本無關。「賣這個價也有人買」就是定價依據。

## 4．需求檢查

區分買家說出來的需求和真實需求：

- 顧客需要的是「購買」這個行為帶來的結果或感受，不一定是「使用」商品本身。
- 很多購買的真實需求是購買本身帶來的情緒滿足。
- 代運營、陪跑類服務，很多顧客買的是有人帶著、有事可做的狀態，知識只佔一部分。
- 多數知識付費在功能上承擔了心理支援的作用。
- 買家願意掏錢的前提通常是：他覺得這筆錢能回本。

## 5．流量與變現關係檢查

- 分別在哪個平台獲客、成交、交付？
- 成交和交付擠在同一個地方，往往有問題。
- 把內容本身當作變現產品，效率最低。
- dontbesilent 的經驗結構：文字平台獲取流量，影片或直播平台成交，LINE做交付。這是參照，不是判斷標準。例如有人直接靠文字變現，預期收入不高時也完全可行；結構不同時，看它和使用者的收入預期是否匹配。
- 流量大小和收入沒有必然關係；看電商指標（成交、客單價、復購），少看內容資料指標。

## 6．規模化檢查

- SOP 能定下來嗎？穩定了才談擴張，不穩定時擴張只會放大混亂。
- 員工能替代老闆嗎？不能的話，這份收入更接近高薪打工。

## 7．成長層級

| 層級 | 描述 | 核心任務 |
| --- | --- | --- |
| 1 | 有人需要這個產品 | 驗證需求存在 |
| 2 | 有人願意付錢 | 完成第一筆交易 |
| 3 | 很多人願意付錢 | 找到可重複的獲客方式 |
| 4 | 持續獲取流量 | 建立獲客系統 |
| 5 | 從流量到品牌 | 從依賴獲客轉向客戶忠誠 |
| 6 | 多產品協同 | 建立產品矩陣 |
| 7 | 行業標準制定者 | 定義規則 |

不能跳層。使用者在第 2 層卻在操心第 5 層的事，直接指出，並把建議收回到當前層的核心任務上。

## 成熟度訊號

在報告裡標註，訊號缺失時寫明它意味著什麼：

| 訊號 | 缺失時的含義 |
| --- | --- |
| 有沒有定價 | 還沒有產品 |
| 有沒有真實付費客戶 | 還在假設階段 |
| 有沒有復購 | 商業模式還沒驗證 |
| 有沒有可模仿的對標 | 缺少可驗證的參照，寫進結論 |
