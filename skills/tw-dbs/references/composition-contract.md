# `/dbs` 多方法處理契約

當前目標需要多個 Skill 時讀取本檔案。先明確方法之間的關係，再安排執行；不要求使用者重新傳送組合提示詞。

## 一、共同約束

- 聚焦同一個當前目標，可以產生配套檔案、多個候選結果或尚有分歧的解釋。
- 完整讀取入選 Skill 和必要引用，核對輸入、證據、許可權和停止條件。
- 每個成員都有明確用途：補上不同環節，或檢驗不同假設。僅僅相關不足以入選。
- 從最少足夠的方法開始，刪除重複貢獻；沒有新資訊增量時停止擴展。
- 交接保留使用者原始材料與約束，區分確認事實、方法推斷和待核實事項。
- 不預設跨任務長鏈，不因多方法處理自行建立代理或擴大許可權。

## 二、互補組合

適用條件：一個目標包含多項必要工作，成員分別負責不同環節。單個 Skill 足夠時直接採用單項。

確定一個負責整體交付的主 Skill，通常以 1 個主 Skill 和最多 2 個輔助 Skill 開始。確需更多成員時，逐項說明現有分工覆蓋不了的必要貢獻；不要為了全面堆疊方法。

分工可以是前置篩選、證據補充、部分製作、驗收檢查等，角色名稱無需固定。每項分工寫清：

- 使用的 Skill 與必要貢獻；
- 輸入、依賴和產出；
- 驗收與停止條件。

按依賴執行：能阻止無效工作的篩選先做，核心產出所需的證據先取得，驗收檢查針對實際產出。獨立部分無需強行序列，但執行方式服從宿主能力和已有授權。

輔助成員只完成當前分工必要的深度，保留硬門檻。主 Skill 彙總有效結果，避免機械拼接多份全流程報告。交付數量服從使用者目標：可以是一篇整稿，也可以是文稿及配套標題等多項產物。

成員結論衝突時，顯示衝突及證據來源，檢查前提；未解決的衝突保留，不用匯總措辭掩蓋。

## 三、對照嘗試

適用條件：同一問題有多種合理解釋或處理方法，透過比較可以減少不確定性；使用者明確要求分別嘗試時，也按本節執行。

先寫清待區分的假設與比較依據。若一個低成本事實問題就能區分，優先取得事實；仍有必要時，通常從兩種方法的有限嘗試開始，不自動展開全部候選。

對照遵循：

1. 各方法使用相同的原始材料和已確認事實，各自形成分析或候選產出；不要把第一種方法的結論作為第二種方法的既定事實。
2. 保留各自假設、依據、缺口和適用條件；不強制建立主輔關係或合併成唯一答案。
3. 對產出比較使用者的驗收條件；對解釋比較事實覆蓋、反證和可驗證預測。文字說服力、使用者覺得像自己、多個方法結論一致，都不足以證明因果或效果。
4. 同一模型的多種分析仍可能共享偏差，不聲稱構成獨立證據。
5. 事實足以淘汰某個假設、得到滿足要求的結果，或繼續比較已無資訊增量時停止。缺現實證據時指出需要觀察什麼，不能憑空宣佈勝出。

對照與組合可銜接：只有實際結果顯示必要時，才將某項結果交給互補能力繼續處理。保留原有不確定性，不把試探性解釋升級成事實。

## 四、停止與調整

以下情況停止相關分支，其他不依賴它的工作可以繼續：

- 前置判斷推翻後續工作的必要前提；
- 缺失必需證據、工具或授權；
- 成員硬邊界衝突，無法在當前目標內調和；
- 繼續嘗試沒有新增資訊，或當前目標已滿足。

停止時交代當前結果、未完成部分、缺口和恢復條件。新事實或反饋推翻前提時，返回入口重新判斷，沿用已有上下文。

## 五、使用者交付

使用者要求執行時，簡短說明必要分工或比較目的，隨後在當前對話中工作。交付實際結果，或當前推進所需的關鍵問題。

開始使用時明確每個 Skill 的標準名和本輪用途；對照時說明分別檢驗什麼解釋，調整成員時說明原因。最終交付簡短保留本輪實際使用的名稱與分工，不讓這些資訊只出現在進度訊息中。僅預讀、推薦、計劃使用或受阻未執行的成員，不列為已經使用；部分執行按實際貢獻描述，不聲稱完成全流程或啟動獨立 Agent。

使用者只要推薦時給出選擇理由與用途差異。需要匯出提示詞時，才把目標、材料、事實與假設、成員關係、依賴、驗收及授權邊界整理成可攜帶的呼叫說明。
